# Field Attendance System

Zero-cost attendance system for government field staff (teachers / Anganwadi / field officers).
PWA marking app + web monitoring console. GitHub Pages frontend, Google Apps Script backend,
Google Sheets datastore, Google Drive photo storage.

Full brief: `docs/BRIEF.md` — read it before any design or architecture work. Do not import it here.

## Hard constraints

- **₹0/month infrastructure.** No paid services, no VPS, no billed APIs. Ever.
- Frontend is **static only** — GitHub Pages cannot run server-side code.
- Backend is **Google Apps Script** (`doGet`/`doPost` web app). Not Node, not Python.
- Target scale: ~1,000 users, 300–500 marking in the same 45-minute window.
- Must work fully offline and sync later without loss or duplication.

## Repo layout

Org model (real data): District → Project (JGN/KDK/SGN) → Sector (27) →
AWC (695). Field cadres AWT/AWH; phones are NOT unique (AWT+AWH pairs share
the centre phone) — identity is `user_id` everywhere.

## Non-negotiable design rules

- **Photo + GPS fix are mandatory for a mark** (district order 2026-08-19): no photo or no location fix → block with a retry prompt, do not save. But a geofence miss, poor accuracy, or any other data-quality problem still NEVER blocks — record it and flag it.
- **Attendance rows are append-only.** Corrections are new rows with a supersedes reference. Never overwrite or delete an attendance row.
- **Every queued record carries a client-generated idempotency key.** Retries must not duplicate.
- **The console never reads the raw attendance sheet.** It reads a pre-computed JSON summary regenerated by a time trigger. Show the user how stale it is.
- **All Sheet writes go through `LockService`** with the narrowest workable lock scope.
- **Retries use exponential backoff with random jitter.** No fixed-interval retry — 400 phones retrying in lockstep at 09:00 is the failure mode.
- Photos are compressed client-side to ≤60 KB before upload. Camera capture only — no gallery picker.
- PINs are salted and iterated. Never plaintext, never in a Sheet column, never in logs.
- Authorisation is enforced **server-side**. A supervisor must not reach another cluster's data by editing a request parameter.

## Privacy / DPDP

This system holds face photos, precise GPS, and phone numbers of identifiable government employees.

- Sheets, Drive folder, and Apps Script project must be owned by an **organisational account**, never a personal Gmail.
- Attendance photos must **never** be world-readable via a Drive share link.
- Every master-data change and attendance override is audit-logged with actor, timestamp, and prior value.

## Working agreement

- **Minimal, explicit edits.** Change only what was asked. State exactly what changed and why. Do not silently refactor working code.
- **No placeholders.** No `// TODO: implement`. If it can't be finished, say so instead of stubbing it.
- **No invented APIs.** If unsure an Apps Script or browser API exists or behaves as described, say so and give a fallback.
- **Patch scripts must be assertion-guarded** — anchor on exact expected text, fail loudly, never apply partial changes silently.
- **Bind by element id**, not by DOM position or class-order assumptions.
- Every build gets a visible **build tag** (`BUILD: vX.Y-YYYYMMDD-HHMM`) rendered in the UI footer so I can confirm which version is actually loaded.
- Serve app shell with `Cache-Control: no-store` during development; only the service worker manages caching.
- Prefer a few large consolidated tool calls over many small ones.
- Quantify claims. "This won't scale" needs a number attached.

## Config

- The Apps Script web app URL lives in `app/js/config.js` and `console/js/config.js`, both gitignored.
  Commit `config.example.js` instead.
- Never commit: script IDs, spreadsheet IDs, Drive folder IDs, deployment URLs, any real user data.

## Verify before reporting done

- `node tools/test-build.js` passes — an app change that does not rename the
  service-worker cache never reaches a phone that already has the old shell
- `/app` and `/console` both load with no console errors on a cold cache
- Service worker registers and the offline queue survives a hard refresh
- A mark made in airplane mode syncs exactly once when connectivity returns
- `tools/load-sim` at 400 concurrent marks completes with zero dropped and zero duplicated rows
